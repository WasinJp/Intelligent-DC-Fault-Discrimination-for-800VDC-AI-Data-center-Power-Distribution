# DEVIATIONS.md — where the firmware differs from the Python reference, and what bounds it

| # | where | difference | why | test that bounds it |
|---|---|---|---|---|
| 1 | fx_onset stream mode (§4.2) | **Baseline-anchored stream detector.** The literal §4.2 detector (pre-window = the 150 µs ending 50 µs before the candidate, sliding every sample) was implemented and measured on the replayed fixtures: onset within ±2 samples in only 78.4 % of records that both modes detect, 538 of 2 160 records (slow benign ramps, high-Z, series arcs) never fire because the sliding baseline absorbs the drift, decisions identical in 95.9 % — it cannot meet the §4.2 acceptance. The implemented detector keeps the sliding window but **freezes the baseline** as soon as the smoothed sample leaves it by more than 0.05 × threshold (≈ 0.25 σ) and **starts the record at the frozen baseline window** (record = quiet 150 µs + departure, Python's record layout); the onset the node uses is re-detected in record mode on that record. A frozen baseline older than 2 375 samples (4.75 ms) is refreshed so the record fits 2 600 samples; the baseline also unfreezes after 75 consecutive samples back inside the band. Hold-off 5 ms after a fire, re-arm after 75 quiet samples. `freeze_factor = 0` restores the literal §4.2 detector. | the node has no record start; the relay must detect a departure from the last quiet state, not from a window that is already moving with the event | host preview on the fixtures, `fx_cli stream` / ctest `m3_stream_vs_record[_prefix]`: freeze 0.05 — onset within ±2 samples 99.65 % (1 972 / 1 979), identical decisions 100.00 % (2 160 / 2 160); with a random quiet prefix of 0–4.75 ms before each record (seeds 1–3): 99.65 / 99.85 / 99.80 % and 99.91 / 99.77 / 99.72 %. Sweep in MILESTONES §M3. To be repeated on the target with replayed waveforms (M3/M4) |
| 2 | fx_filters IIR type | the SOS band-pass and the anti-alias decimator run in **double**, not float32 (spec §1.3 expected float32, §6.2 allowed 1e-4 on spec_i/spec_v for it) | float32 state/coefficients miss the tolerance: spec_i off by up to 4.0e-4 in 126 of 6 480 rows, spec_v 1.9e-4 in 14 (MILESTONES §M1.3); in double the cascade is bit-identical to `scipy.signal.sosfilt`. The M7 fpv5-d16 has hardware double. Build with `-DFX_IIR_FLOAT=ON` to reproduce the float32 numbers | unit test `unit_common` (0 error vs scipy); `m1_feature_agreement`; M3 will report the per-block DWT cost of the double filter |
| 3 | fx_features arithmetic | all feature arithmetic in double (the samples are converted from codes in float32, exactly like the numpy reference, then promoted) | the 1e-6 relative criterion cannot be met in float32 for small differences of large means (di_end, v_sag_end); double costs nothing on the critical path (125-sample window) | `m1_feature_agreement`: ≤ 1.5e-10 relative on every feature |
| 4 | compiler flags | `-ffp-contract=off` on host and target | GCC fuses `b0*x + z1` into an FMA on Cortex-M7 (fpv5) by default, which changes IIR rounding vs scipy and breaks host/target determinism (§1.4) | host build uses the same flag; node and bench_control builds too; M3 parity test (§6.4) |
| 5 | fx_features normalisation | features are computed in physical units and divided by I_rated / V_ref at the end, in the Python order, not scaled to p.u. before the features (spec §3 wording) | keeps every operation in Python's order so rounding matches; mathematically identical | `m1_feature_agreement` |
| 6 | fx_model tables | thresholds and leaf values stored as exact float64 in a 12-byte packed node (spec left the layout open; a float32 first attempt was rejected). sklearn's +inf thresholds (missing-value-only splits) are emitted as `INFINITY` | sklearn thresholds are midpoints of training values; grid-valued features (t_rise = k/fs·1e3) land exactly on them and float32 rounding flipped 12 splits in the fixture set (raw score error up to 1.4). Cost: 12 bytes per node | `m2_model_agreement`: bit-identical scores, 9 720 rows |
| 7 | fixtures (make_fixtures) | the 500 kSa/s record is requantised to 16-bit codes with a per-record gain (base ±8 × I_rated / ±4 × V_ref, doubled only when a record would clip: 20 of 2 160); the Python reference is computed on the reconstructed float32 values, not on the unquantised decimated stream; slow streams stored for 135 of 1 080 events | the node holds codes, and the reference must be computed on what the C code sees; the 50 MB cap (43 MB records + 4.8 MB CSV) | requantisation effect reported in `fixtures/manifest.json` (MILESTONES §M1.1); acceptance is agreement on the record |
| 8 | tools (Python side) | feature CSVs are read with `float_precision="round_trip"` (`train_model.py`, `export_model.py`, `compare.py`, `budget_study.py`) | pandas' default parser is not correctly rounded: it read `0.030000000000000002` (a t_rise value) one ulp low, onto the wrong side of a split, and made the *reference* disagree with the exact C parse. The dcsim studies still use the default parser; the trained bins can therefore differ by ulps from a model trained through `studies._cv_predict` | `m2_model_agreement` |
| 9 | model training (`train_model.py`, `studies._fit`) | **sklearn `early_stopping='auto'` is ON above 10 000 rows.** `_fit` (max_iter 300) trained on the v1xl6k tables (36 000 rows) stops after 72 / 82 / 102 iterations (feeder / rack / both), with a 10 % validation split taken out of the training rows; on the 6 201-row v1large044 tables it ran all 300. This is not a firmware deviation — the committed models are exactly what `_fit` produces — but it is a property of every v1xl / v1xl6k study in the repo and it shapes the §7.4 budget table (docs/TIMING.md): "300 iterations" never existed for those tables. `--early-stopping off` builds the stated number of trees | docs/TIMING.md compares `auto` with 100 / 150 / 300 fixed trees at the 0.1 % false-trip budget |
| 10 | fx_cadence (M5, host side) | the double learner uses a radix-2 FFT on a power-of-two length ≥ 2n (numpy: rfft of length 2n); `np.percentile` / `np.median` / `scipy.find_peaks` (plateau midpoints, wlen=None prominences) are reimplemented; the learner state is 4.5 MB (host only) | the host port fixes the semantics first | `m5_work_agreement`: has_period exact, period_strength ≤ 4.6e-13, phase_err ≤ 2.8e-14 on 810 rows; relearn 5.8 ms mean on the host |
| 11 | node image (M3) | the decision (record-mode features + inference) runs in PendSV at a lower priority than the 16 µs DMA block interrupt, not inside it; the window close is time-stamped in the block interrupt that completes the window; the record passed to the extractor is `[baseline start, k_on + N_W)` (≤ 2 600 samples), which gives the same features as the full 2 600-sample record (every feature uses samples < k_on + N_W) | a 50–100 µs decision inside the block interrupt would overrun the 2 × 8-word DMA buffer; this keeps the acquisition deterministic and costs one PendSV entry (~1 µs) | DWT `close->trip` in `status` / `timing` (M3 procedure §4); §7.4 budget |
| 12 | fx_cadence32 (M5 target learner) | (a) the history holds the **current channel only** as float32 (152 kB), not both channels (304 kB): no feature reads the slow voltage; (b) the autocorrelation is computed as **block cross-correlations** with 4 096-point real FFTs (CMSIS-DSP `arm_rfft_fast_f32`; 8 192-point own radix-2 on the host build) accumulated in float32, instead of one FFT of length 2n (which would need 1 MB); (c) every float32 peak lag is **refined exactly** in double over ±4 lags (O(n) per lag) so the one-bin plateau wander of float32 disappears; (d) order statistics (percentiles, medians) use an exact two-step selection (sorted float32 shadow + tie resolution on distinct doubles), the smoothed series are computed on the fly in double, the tier-1 state is a bit field. Memory on the H743: AXI SRAM 497 kB (history, shadow, ac, acc, cnt, state, peaks), D2 48 kB (FFT work), D3 48 kB (published edges), DTCM 24 kB (learner edges) | the H743 has 1 MB of SRAM in four regions; the double learner needs 4.5 MB | `m5_f32_agreement` (generic FFT) and `m5_cmsis_agreement` (CMSIS-DSP): has_period exact, period_strength ≤ 2.6e-13, phase_err ≤ 2.8e-14 on 810 rows — the same precision as the double learner. Before the exact refinement 3 events had a tier period off by one bin (0.2 ms), before the tie fix one event had an edge shift |
| 13 | fx_can / can_link (M6) | the spec's **one 16-byte frame** (P(TRIP), has_period, phase_err, onset) cannot carry what the 30-feature two-node model needs: the sender's 15 features. The node sends the 16-byte summary first (within 20 µs of the close, §7.3) and then **three 64-byte CAN-FD frames** with the 15 features as exact float64 (float32 would flip tree splits, #6). The feeder waits up to `can_wait_us` (settings, default 50 µs) for a complete rack set whose onset is within `onset_tol` (default 500 samples) and otherwise uses its own model; the path is logged (`used_two_node`). At 5 Mbit/s the three frames take ≈ 150–250 µs, so the 50 µs window of §7.3 will not be met with these frames; the wait is a bench decision | `unit_common` (frame round trips, routing); M6 procedure §B on hardware |
| 14 | cadence relearn budget (§5: every 200 ms, < 20 % CPU) | host measurement of the target learner: 23.0 M x86 cycles mean / 196 M max per relearn (CMSIS backend, 63.5 FFTs). Projected 70–150 ms mean and 0.4–1.2 s max on the M7 at 480 MHz if it needs 1.5–3× the x86 cycle count: the 40 ms budget is **not met by the projection**. `CADENCE_PERIOD_MS` is 200 as specified; the M3/M5 procedure measures `relearn` cycles (DWT) and the period is to be raised to 1 s (7–15 % CPU) or the lag range shortened if confirmed | `timing` → `relearn` on the target; TIMING.md §3 |
| 15 | record upload (§8) | the uploaded record is `[rec_start, rec_start + 2 600)` where `rec_start` is the baseline start of the decision (#1), not `[k_on − 100, k_on + 2 500)`; the trailer carries the absolute `k_on`, the decoder converts it to record coordinates | the host must be able to reproduce the node's features from the uploaded record (`record_decoder.py` + `fx_cli extract` + `compare.py`); with `k_on − 100` as the start it could not when the baseline was frozen earlier | M6 procedure §C: node trailer vs host extract on the uploaded record |
| 16 | bench_control (§10) | console on the ST-Link virtual COM port (a USB serial; the H7's own USB is kept for the node's record stream); scheduler tick 100 µs (events are placed on that grid; the fault trigger edge itself is a 5 µs GPIO pulse into the hardware one-shot); staircase ramps switch the load branches one at a time, largest first, at ramp/5 intervals; a SYNC pulse is emitted at every scheduled edge, every manual step and every fault trigger; the firmware refuses a fault when the arm key sense input is low, in addition to the hardware key switch in series with the one-shot outputs | hardware and schedule of SCHEMATIC_DESIGN §3 / SCALING_SHEET §7 | M7 procedure §D |
